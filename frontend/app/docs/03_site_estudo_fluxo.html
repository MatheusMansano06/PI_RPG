Resumo do projeto

O que o app faz

O app orienta calouros pelo Campus I usando uma história gamificada. O aluno entra, vê o mapa, caminha até o local da missão, conversa com um personagem, responde uma pergunta e libera a próxima fase.

O foco do app é explicar o campus de um jeito mais leve, misturando localização real com narrativa.

Como o código foi separado

screens guarda as telas que o usuário vê.

services guarda regras como login, GPS, progresso e áudio.

data guarda o roteiro das fases.

models guarda os formatos dos dados.

widgets guarda peças visuais reutilizadas.

Explicação em uma frase

O app começa no main.dart, abre a splash, vai para login, depois menu, prólogo, mapa, personagem, pergunta e conclusão da missão. A conclusão chama o serviço de progresso e libera a próxima fase.

Mapa mental rápido

Entrada

main.dart e splash iniciam o app.

Usuário

Login/cadastro conversam com o backend.

Jogo

Mapa e roteiro controlam a missão atual.

Progresso

Service marca fase concluída e libera próxima.

Trechos de código para estudar

Estes blocos mostram os pontos que mais explicam o funcionamento do app.

1. Entrada do app lib/main.dart

O app começa chamando runApp. O home decide a primeira tela.

void main() {
  runApp(const MyApp());
}

return MaterialApp(
  title: 'RPG Interativo Campus I',
  theme: AppTheme.light,
  home: const SplashScreen(),
);
2. Splash para login screens/step_01_splash_screen.dart

Depois do tempo da splash, o app troca para a tela de login.

void initState() {
  super.initState();
  _timer = Timer(const Duration(seconds: 2), _goToLogin);
}

void _goToLogin() {
  AudioManager().playBgm();
  CinematicAudioService.instance.playCloudTransition();
  Navigator.of(context).pushReplacement(
    buildCloudRoute(const LoginScreen()),
  );
}
3. Login ou cadastro screens/auth/step_02_login_screen.dart

A variável _isRegisterMode decide se usa login ou cadastro.

if (_isRegisterMode) {
  await _authService.register(
    nome: _nomeController.text,
    email: _emailController.text,
    senha: _senhaController.text,
  );
} else {
  await _authService.login(
    email: _emailController.text,
    senha: _senhaController.text,
  );
}
4. Mapa liga GPS screens/game/step_05_map_game_screen.dart

Quando a tela do mapa abre, ela valida a chave e começa a localização.

void initState() {
  super.initState();
  _verificarConfiguracaoMaps();
  _iniciarLocalizacao();
}
5. Encontrar fase atual screens/game/step_05_map_game_screen.dart

O mapa pega o ID da fase atual no service e procura no roteiro.

GameEnvironmentModel? get _currentEnvironment {
  final currentId = _progressService.ambienteAtualId;

  for (final environment in roteiroFases) {
    if (environment.id == currentId) {
      return environment;
    }
  }

  return null;
}
6. Resposta da pergunta screens/game/step_08_stage_challenge_screen.dart

Se acertar, toca som certo e libera botão de conclusão.

void _selectOption(DialogueOptionModel option) {
  if (option.correta) {
    AudioManager().playCorrect();
  } else {
    AudioManager().playWrong();
  }

  setState(() {
    _selectedOption = option;
    _completed = option.correta;
  });
}
7. Concluir missão services/step_04_game_progress_service.dart

Atualiza a lista de fases concluídas e calcula a próxima.

void marcarComoConcluido(String ambienteId) {
  final concluidos = {..._progress.ambientesConcluidos, ambienteId};
  final proximo = obterProximoAmbiente(concluidos);

  _progress = GameProgressModel(
    ambienteAtualId: proximo?.id,
    ambientesConcluidos: concluidos,
  );
}

Services do projeto

Services são classes que guardam regras ou chamadas importantes. A ideia é tirar regra pesada das telas.

Arquivo Para que serve Onde é chamado
step_01_auth_service.dart Faz login, cadastro e valida campos. step_02_login_screen.dart
step_02_localizacao_service.dart Pede permissão de GPS e lê posição atual. step_05_map_game_screen.dart
step_03_location_check_service.dart Consulta backend para teste/verificação de localização. step_05_map_game_screen.dart
step_04_game_progress_service.dart Guarda fase atual e fases concluídas. Mapa, progresso, conclusão e final.
step_05_audio_manager.dart Toca música de fundo e efeitos de clique/acerto/erro. Main, botões e pergunta da fase.
step_06_cinematic_audio_service.dart Toca som curto de transição. Splash e login.

Como explicar services para banca

“A gente separou services para não colocar todas as regras dentro das telas. Por exemplo: a tela de login não faz HTTP direto; ela chama o AuthService. A tela do mapa não pede GPS sozinha; ela chama o LocalizacaoService. Assim fica mais organizado e mais fácil de estudar.”

Android, iOS, mapa e backend

Android frontend/app/android

Guarda configurações Gradle, AndroidManifest e chave Android do Google Maps em local.properties.

iOS frontend/app/ios

Guarda projeto Xcode, Info.plist, Podfile e chave iOS do Google Maps em GoogleMapsKeys.xcconfig.

Como o mapa funciona

1

Verifica chave do Maps

O app usa MethodChannel para perguntar ao Android/iOS se a chave foi configurada.

2

Pede permissão de GPS

LocalizacaoService chama o Geolocator para pedir permissão e ler posição.

3

Calcula distância

O app compara a posição do aluno com a coordenada da missão atual.

4

Libera fase

Se a distância for menor que raioMetros, o botão de entrar na missão fica disponível.

Backend

O backend fica em backend/apiRpg. O app usa principalmente as rotas de autenticação:

POST /auth/login

POST /auth/register

GET /auth/health

“Nosso app começa no main.dart, que carrega a splash. A splash leva para login/cadastro. Depois o usuário entra no menu e inicia a jornada. O mapa usa GPS para verificar se o aluno está perto do local da missão. Quando entra no raio, a fase abre.
